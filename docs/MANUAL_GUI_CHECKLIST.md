## 历史版本与逐项检查要求

2026-10-23，用户报告已经检查三个角色的客户端使用效果，记录为 `USER_REPORTED_GUI_CHECK_COMPLETED`。逐角色选中/加载/显示为 `USER_REPORTED`；未提供客户端版本、图集哈希、逐状态观察、主题/尺寸、重启或截图证据。下表表示逐状态独立检查，仍为 `NOT_RUN`，不能据笼统报告填写 PASS。离线图集/GIF与安装文件是独立证据。Computer Use 对宿主 `com.openai.codex` 的拒绝是应用安全限制，不通过其他渠道规避。

每个角色约需一次完整检查；无法触发的状态保留待验，不强行填写通过。

1. 记录日期、检查者、实际客户端版本、系统“减少动态效果”设置、宠物大小及已安装图集 SHA-256。动画检查时需要关闭减少动态效果；检查完可恢复用户原设置。
2. Settings → Pets → Refresh，选择对应角色，用 `/pet` 或命令菜单 Show pet 显示。未找到入口或角色未出现就记录实际情况。入口依据[官方文档](https://learn.chatgpt.com/docs/pets)，以当前版本为准。
3. 在浅色与深色桌面观察轮廓和边缘；观察实际出现的动画及切换，记录可复核的证据。无法自然触发的状态保留 NOT_RUN，不以缺少录屏推断失败。
4. 手动左右拖动，观察左右朝向、移动动作及停止后回待机。执行一个正常且无外部写入的任务，观察工作状态；任务需要输入时观察等待。使用客户端可用的审阅流程检查审阅动作。
5. 挥手、跳跃、失败若有客户端明确的触发入口，按其提示操作；没有入口或未自然出现就写 `NOT_RUN`，不为了触发失败执行危险命令。不把活动标签本身当作动画行证据。
6. 切换三角色并重启客户端后再检查选择持久化、透明背景、首帧、状态切换及缩放。减少动态效果开启时单独确认静态首帧，这是独立检查项。

角色重点：蓝发看发侧蓝结、围裙鲸图、长发和鲸尾；橙花看左侧花饰/黑结、右臂书本、封面、裙摆与手；银白看双角、翼根、连续鳞尾、白发白裙浅底边界，独立云灵不能变成人体或消失。记录具体状态与帧相位，不笼统写“全部正常”。

每项记录 `PASS / FAIL / NOT_RUN`、实际触发步骤、主题/大小、观察结果和私有证据路径及 SHA-256。证据留在忽略的 `workruns/`；不得上传含角色或私人界面的截图。`visual_qa.rows` 需对离线九行全部 PASS；`gui_qa.rows` 需列出九行，实际通过写 PASS，未触发写 NOT_RUN，已观察失败不能发行。客户端基本兼容性需要 `gui_qa.status=PASS`、检查者及哈希绑定的证据，并在 `gui_qa.checks` 中将 `load`、`display`、`movement` 分别记为 PASS；能自然触发的工作状态如实记录。九行 GUI 全部 PASS 的旧证据格式仍可使用。机器门禁不证明证据内容属实，需人工审阅。

跨状态重点：从移动/跳跃返回待机，从工作转等待或审阅，再回待机。书本闭合↔打开、侧身↔正面、蹲姿↔站姿在固定行切换时可能硬切；检查是否仍是同一角色、道具与人物侧一致、落点合理。记录任意帧中断的真实情况，离线端点审查不能覆盖客户端全部中断调度。
